## Operating Rules (apply every session)
- **Engine constants:** EMA=10, SMA=40, COST=0.0005, CAPITAL=100000. Universe = 1,435 stocks + 28 ETFs (`tbl_stock_tickers.is_etf`, `tbl_etf_tickers`). PostgreSQL `swingtrader-db` on `127.0.0.1:5432` (docker). Backtests read scanner tables only.
- **MTF state is DB-backed** (`mtf_pending`/`mtf_runs`/`mtf_positions`/`mtf_trades`); `mtf_positions` = source of truth; MTM in Slack = held qty × close. `get_pending`/`save_pending` cast JSONB `::text`. **`save_pending` deletes all unconsumed for the mode before INSERT — never restore same-sig_date DELETE** (crashes `idx_mtf_pending_unconsumed`).
- **Daily-data completeness is a COVERAGE FRACTION, never a fixed ticker count** (`runner.py` `_ensure_daily_data`): `COVERAGE_DATE_PICK = 90%` picks the newest settled date (`date < today`) for the cohort; `COVERAGE_TRADE_FLOOR = 99%` refuses to trade it without a backfill retry. The retired `MISSING_TOLERANCE = 5` was knife-edge — six thin names Alpaca had no bar for (CSM/PLBC/QCRH/SENEA/UNTY/UTMD) made 2026-09-28 settle at 1419/1425, which rolled the whole stock leg back a session to 09-25 (re-trading yesterday's signal set while the ETF leg scored 09-28) *and* burned ~15 min of futile backfill retries before aborting the leg. Individual laggards are the `STALE_LAG_DAYS` guard's job, not either bar's.
- **emasma scoring reads settled bars only:** `sig_date` = last COMPLETE daily date (never live/partial), tie-break sort `(-score, -gap_w)` — live == backtest, reproducible. Ratchet uses settled daily bars + `latest_settled_daily_closes`; ratchet-sold names get same-day cool-off via `mtf_ratchet_cooldown` (stock leg only). **Staleness guard baseline is capped at `sig_date`** (`runner.py`: `baseline = min(get_last_complete_daily_date(...), sig_date)`) — it must never be NEWER than the date being scored, or the 1-day tolerance wipes the universe (2026-09-28: 1,435/1,435 excluded, both legs `no qualifying picks`, zero orders; same wipe on the ETF leg 2026-09-14). `get_last_complete_daily_date` counts today's *intraday* rows once the self-heal backfill + hourly sampler cross 90% coverage, so on Mondays the settled bar is 3 calendar days back and every ticker trips the guard.
- **MTF executor self-heals until the close (2026-09-28):** `swingtrader-mtf-executor.service` runs `executor_retry.py`, not `runner.py` directly. Loop = retry the **score** step (both legs) every 30m until `runner.py` exits 0 (it has all the tickers' data) or 16:00 ET, then run the **execute** step once, then exit. Consequence: `run_all`/`run` return a bool and `__main__` does `sys.exit(0 if ok else 1)` — a leg that failed or produced no candidates must be non-zero, or the orchestrator can't see it. Sector/regime info is informational and never fails the run. Each attempt re-runs the score step's own self-heal (backfill + Data Readiness Gate), so waiting is what acquires missing bars. `RuntimeMaxSec` is **ignored** on `Type=oneshot` — the cap is `TimeoutStartSec=6h`. Deadlock trap: systemd will not re-trigger a unit that is still active, so a runaway loop silently skips the next morning — the 16:00 stop + `TimeoutStartSec` are the guards.
- **MTF is weekly-only by design** — hourly (`tbl_scanner_tickers_1hour`, 16 hash partitions) is unreliable. Daily Signal is the sole live hourly consumer; treat its signals as day-old/eyeball, never auto-execute.
- **CoreEW family — full narrative/history/decisions in `common/docs/coreew_family.md`.** Live = **LegEMA P20w**: `TradeExecutorService::runLegEma(dryRun, span, override)`/`replayLegEmaSeries`/`legEmaTrail`/`legEmaState` — per-leg weekly EMA(20) crossover (ewm adjust=False, alpha 2/21, seeded at first close), OFF legs in cash, ON legs EW-rebalanced each new settled week; settled weeks only (`d.date + 7 <= CURRENT_DATE`), Friday close decides, Monday fills; systemd `swingtrader-legema.timer` Mon–Fri 10:05 ET (after 30-min warm-up). **Parity exact BY CONSTRUCTION:** `backtest_trio_ew.py --leg-ema N` consumes `trades:coreew-leg-ema-series` (PHP) — the signal is never re-implemented; **any new CoreEW variant must be added in PHP**. P{span}d (daily-close CO) is a dead-end, Python-only, never live. **Dedupe = atomic DB claim on `coreew_runs`** (unique strategy/span/week; `insertOrIgnore` → PG `ON CONFLICT DO NOTHING`) — cluster-safe single weekly actor; dry-run never claims/writes; `--override` releases the week's claim; errors → claim released, retry next tick. Fill: trim-before-top-up; exits via `rebalanceTrim` (or direct sell gated on `waitForOrderFill`), buys via `rebalanceTopUp`. Rollback = re-enable EG100 crontab line (books hand over cleanly — both target EW among the 3 legs).
- **CoreEW half-trim experiment (2026-09-28) — measured, REJECTED, never live.** `replayLegEmaTrimSeries`/`legEmaTrimTrail` (PHP) + `trades:coreew-leg-ema-trim-series` + `backtest_trio_ew.py --leg-ema-trim EXIT:TRIM` implement "dip below EMA(TRIM) → hold half the leg, recross → top back up, below EMA(EXIT) → exit fully" (settled weekly, freed half in cash). It reads its **exit leg from the live `replayLegEmaSeries()`**, so the 20W gate is the live gate; there is **no driver, no timer and no order path** — `exposure` feeds the backtest only. Result: 2016+ P20w +360.0%/−19.2% vs +T10 +294.0%/−18.4% — **CAGR −1.1 to −1.7 pts for a FLAT MaxDD**, same ordering in the 813d window and at every trim span. The 20W exit already does the risk work; a 10W cross in an uptrend is a shallow dip whose bounce the trim donates. Keep the code for the record; **do not wire it to cron/live.**

- **Alpaca key routing (3 pairs + scanner)** — see `common/docs/ALPACA_KEYS.md`. - **Backtests:** **A/B only** — `current` vs new variant on BOTH legs (`--exit ratchet-atr --ratchet-atr-src daily`), head-to-head table + "keep current"/"switch" rec. Don't re-run settled variants (daily-bull, gap-reverse, close-200, fresh — keep as research flags). **Backtest returns are NOT trustworthy as returns** (survivorship bias, idealized fills, untrimmed winners; +17K%↔+20M% from tie-break alone) — relative signal quality + replicable-picks only. **Weekly-bar rule (2026-09-25):** `backtest_topn_multitf.py` reads the last COMPLETED weekly bar by default (row ≤ decision date − 7d, same as live `_settled_weekly_idx`); the old decision-day-Monday read was a 4-day lookahead (ETF-28 top-3: +636% legacy vs +106% settled); `--legacy-weekly` reproduces old numbers; **every pre-2026-09-25 figure is stale**. Stock leg re-run lookahead-free (top-25 EW, daily-ATR ratchet, 2021-09→2026-09, cost 0): +952%/−32.9% DD/45% win vs +3.05M% legacy — survivor-universe inflated (~3× real IJR/IJH/IWM), ~50-name dependent, **not an expected return** (config.py note). Baseline cache: `backtest_baseline_cache.json` via `--cache-baseline` (stock 2021-09-20→2026-09-16, ETF 2020-03-02→2026-09-16); refresh when comparing new data. **Never change the live emasma path without user sign-off.**
- **Settled-bar rule (BAND/DOCN 09-16):** validate any DCO/HCO flip against the last settled bar (`date < today`), never the live/partial bar. Daily Signal hourly is quality-gated (`vol >= 1000`).
- **Server uptime (2026-09-27 correction — there is NO power window):** **nothing on this box enforces any on/off window** — no systemd unit, cron entry or script powers it off. **Real fragility is the MORNING:** the 09:00 `scanner-update` timer rarely fires at 09:00 — it fires on boot (~09:32). `Persistent=true` rescues it and still beats the 10:25 MTF executor that depends on it, but the margin is ~50 min: a boot after 10:25 means missing daily bars at execute time with no warning. All timers are `Persistent=true`. `swingtrader-optimizer.timer` (CHAND) is `disabled`; `swingtrader-mtf-scorer.timer` is enabled/active — Mon–Fri 16:45 evening recap (re-score, same Slack summary, no orders; harmless since `save_pending` gets overwritten next morning). Do not design schedules around 17:10. Full live-service inventory: `common/docs/services_doc/README.md`.
- **Known code invariants:** `syncLiveTradesFromAlpaca` skips `status !== 'open'`; never overwrite `alpaca_order_id` in `handlePooledEntries`; executor buy path falls back to live Alpaca position qty; `reconcile_trades.py` rebuilds `mtf_trades` from Alpaca fills. `ema10_sma40_crossover`/`sma_crossover`/MACD/PPO columns were DROPPED 2026-09-26 (lookahead-biased legacy artifacts) — compute EMA10/SMA40 inline (`ScannerController::closeSma40Ema10` streams the last 120 bars; ~3s vs ~49s for the recursive-CTE version it replaced). `atr_stop` is the only stored indicator. `_nearest_date_idx` fallback for daily data. **CoreEW fill discipline (2026-09-21):** `POST /v2/orders` answers with the order still `new`/`accepted` and `filled_avg_price` null — never record a DB trade or claim one in Slack until `waitForOrderFill` confirms `status=filled` and yields the real `filled_avg_price`. `rebalanceTrim` returns the actual fill price (0 = not filled → no DB/Slack claim). `ExecuteEWETF` also gates: no live trading during the first 30 min of the session (09:30–10:00 ET warm-up, blocks all live paths incl. `--override`).
