## Operating Rules (apply every session)
- **Engine constants:** EMA=10, SMA=40, COST=0.0005, CAPITAL=100000. Universe = 1,435 stocks + 28 ETFs (`tbl_stock_tickers.is_etf`, `tbl_etf_tickers`). PostgreSQL `swingtrader-db` on `127.0.0.1:5432` (docker). Backtests read scanner tables only.
- **MTF state is DB-backed** (`mtf_pending`/`mtf_runs`/`mtf_positions`/`mtf_trades`); `mtf_positions` = source of truth; MTM in Slack = held qty × close. `get_pending`/`save_pending` cast JSONB `::text`. **`save_pending` deletes all unconsumed for the mode before INSERT — never restore same-sig_date DELETE** (crashes `idx_mtf_pending_unconsumed`).
- **emasma scoring reads settled bars only:** `sig_date` = last COMPLETE daily date (never live/partial), tie-break sort `(-score, -gap_w)` — live == backtest, reproducible. Ratchet uses settled daily bars + `latest_settled_daily_closes`; ratchet-sold names get same-day cool-off via `mtf_ratchet_cooldown` (stock leg only).
- **MTF is weekly-only by design** — hourly (`tbl_scanner_tickers_1hour`, 16 hash partitions) is unreliable. Daily Signal is the sole live hourly consumer; treat its signals as day-old/eyeball, never auto-execute.
- **CoreEG100 logic (Laravel `TradeExecutorService`) — LIVE 2026-09-27, replaces variant S.** `runEg100Gate(dryRun, span, override)` + `replayIndexEgGate()` + `indexEgGateState()`: builds an equal-weight (daily-rebalanced) QQQ/VTI/VTV index from settled daily closes (seeded 1.0, day-0 return 0) and compares it to its own `ewm(span=100, adjust=False)` EMA (alpha 2/101, seeded at the first index value) as a PURE crossover — no band. LONG = all 3 at equity/N, OFF = all 3 flat; it is a whole-book decision, not per-leg. Settled bars only (`date < CURRENT_DATE`) so a day-t decision is acted on in session t+1. **Parity with the backtest is exact, verified over the full 2698-bar history: index+EMA to 1e-6 and all 103 flip dates/states identical** (`--json` re-runs the check). Backtest (`backtest_trio_ew.py --ema-gate 100`) vs weekly EW rebalance: +73.5%/−8.4% DD (3y), +96.6%/−16.1% (5.5y), holdout 2016-11→2021-04 +85.6%/−12.1% (64% of DD removed, 70% of return kept); the ±3% band variant beat pure crossover out-of-sample and lost in-sample, so EG100 is the conservative pick, NOT a proven optimum. Cutover: dedupe key = newest flip date (`storage/coreew_eg100_last_flip.txt`), so it acts once per state change and re-runs are NO-OPs (errors → NOT recorded → retry next tick; dry-run never writes); trim runs BEFORE top-up because top-up alone cannot converge the unequal book S left behind. Exit = `rebalanceTrim` when a DB trade exists, else direct market sell gated on `waitForOrderFill`. **⚠ TIMING: the backtest fills at t+1 CLOSE; live fills intraday when the 5-min cron runs — the backtest is not a promise about the live fill price.** Shares the 30-min opening warm-up gate (09:30–10:00 ET) + `--override`/`--dry-run` with the other CoreEW drivers. **Variant S (`runMonotoneGate`/`replayMonotoneGate`, `trades:execute-EW-gate`, dedupe `storage/coreew_gate_last_week.txt`) is RETAINED but off the cron** — it was the weekly per-leg peak−2·ATR ratchet, whose honest live-timing result (variant S `--settled-friday`) was +28.4%/−29.3% DD, i.e. worse than EW buy-and-hold. Rollback = uncomment the retired crontab line. The older EW guardrail path (`rebalanceEqualWeightWeekly`, `rakeEqualWeight`) is also retained, uncalled.
- **Alpaca key routing (3 pairs + scanner)** — see `common/docs/ALPACA_KEYS.md`. CoreEW keys → `swingtrader/backend/.env` AND `scanner/backend/.env` (scanner is read-only IEX consumer on CoreEW keys; missing scanner update silently stalls hourly/ETF capture). MTF stock/ETF keys → `swingtrader/services/mtf/.env` (distinct var names).
- **Backtests:** **A/B only** — `current` vs new variant on BOTH legs (`--exit ratchet-atr --ratchet-atr-src daily`), head-to-head table + "keep current"/"switch" rec. Don't re-run settled variants (daily-bull, gap-reverse, close-200, fresh — keep as research flags). **Backtest returns are NOT trustworthy as returns** (survivorship bias, idealized fills, untrimmed winners; +17K%↔+20M% from tie-break alone) — use only for relative signal quality + replicable-picks validation. **Weekly-bar rule (2026-09-25):** `backtest_topn_multitf.py` now reads the last COMPLETED weekly bar by default (row dated ≤ decision date − 7d, same as live `_settled_weekly_idx`); the old decision-day-Monday read was a 4-day lookahead (ETF-28 top-3: +636% legacy vs +106% settled) — `--legacy-weekly` reproduces old numbers only. Every cached baseline and every pre-2026-09-25 backtest figure predates the fix and is stale. Stock leg re-run lookahead-free (top-25 EW, daily-ATR ratchet, 2021-09→2026-09, cost 0): +952% / −32.9% DD / 45% win vs +3.05M% legacy — survivor-universe inflated (EW universe ~3× real IJR/IJH/IWM) and ~50-name dependent (ex-top-50: +132% vs +115% EW rest); not an expected return (see config.py note). Baseline cache: `backtest_topn_multitf.py` + `backtest_baseline_cache.json` via `--cache-baseline` (stock 2021-09-20→2026-09-16, ETF 2020-03-02→2026-09-16); refresh baseline when comparing against new data. Never change the live emasma path without user sign-off.
- **Settled-bar rule (BAND/DOCN 09-16):** validate any DCO/HCO flip against the last settled bar (`date < today`), never the live/partial bar. Daily Signal hourly is quality-gated (`vol >= 1000`).
- **Server uptime (2026-09-27 correction — there is NO power window):** earlier docs claimed ON 09:00→10:30 + 16:30→17:10 ET, but **nothing on this box enforces it** — no systemd unit, no cron entry, no user unit, no script powers it off. The window was manual discipline that was never automated. Observed from `journalctl --list-boots`: boots land **09:32–10:01**, shutdowns happen **15:07–21:35** (highly variable). The morning half is roughly real; the evening cutoff is not. Do not design schedules around 17:10 — e.g. `weekly-takeoff` (Fri 17:15) demonstrably runs (last fired 2026-09-25 17:16:55 on a day the box was up until 19:08). **Real fragility is the MORNING:** the 09:00 `scanner-update` timer rarely fires at 09:00 — it fires on boot (2026-09-25: 09:32:54). `Persistent=true` rescues it, and 09:32 still beats the 10:25 MTF executor that depends on it, but the margin is ~50 min, not ~85. A boot after 10:25 means missing daily bars at execute time with no warning. All timers are `Persistent=true`. CHAND optimizer timer disabled (confirmed 2026-09-27: `swingtrader-optimizer.timer` is `disabled`). **Correction 2026-09-27:** the MTF scorer timer is NOT disabled — `swingtrader-mtf-scorer.timer` is enabled/active, running Mon–Fri 16:45 ET as an evening-recap re-score that posts the same Slack summary the 10:25 executor posts (no orders; harmless re-run since `save_pending` gets overwritten by the next morning's inline score). See `common/docs/services_doc/README.md` for the full live-service inventory.
- **Known code invariants:** `syncLiveTradesFromAlpaca` skips `status !== 'open'`; never overwrite `alpaca_order_id` in `handlePooledEntries`; executor buy path falls back to live Alpaca position qty; `reconcile_trades.py` rebuilds `mtf_trades` from Alpaca fills. `ema10_sma40_crossover`/`sma_crossover`/MACD/PPO columns were DROPPED 2026-09-26 (lookahead-biased legacy artifacts) — compute EMA10/SMA40 inline (`ScannerController::closeSma40Ema10` streams the last 120 bars; ~3s vs ~49s for the recursive-CTE version it replaced). `atr_stop` is the only stored indicator. `_nearest_date_idx` fallback for daily data. **CoreEW fill discipline (2026-09-21):** `POST /v2/orders` answers with the order still `new`/`accepted` and `filled_avg_price` null — never record a DB trade or claim one in Slack until `waitForOrderFill` confirms `status=filled` and yields the real `filled_avg_price`. `rebalanceTrim` returns the actual fill price (0 = not filled → no DB/Slack claim). `ExecuteEWETF` also gates: no live trading during the first 30 min of the session (09:30–10:00 ET warm-up, blocks all live paths incl. `--override`).
